# v0.13.7

## Normal Forward URL input

- Operators enter the normal Forward tenant URL, such as `https://fwd.app`, instead of manually adding `/api`.
- The app validates an HTTPS origin and normalizes it to the Forward `/api` root inside the backend before creating a
  client.
- Existing saved connections ending in `/api` remain compatible and normalize to the same API root.
- Credentials, query strings, fragments, HTTP URLs, and any other URL path remain rejected.

## Upgrade note

Deploy v0.13.7 as a new immutable app version. The Forward connection settings schema advances to v3.1 while retaining
the existing field and accepting both the new origin form and the legacy `/api` form, so operators do not need to
rewrite existing saved connections.

This usability change does not alter Forward endpoints, access profiles, Credential Vault handling, TLS verification,
mutation approval, or the application-flow acceptance boundary.

## Source verification

The v0.13.7 source candidate passed the full repository CI, Dynatrace app build, and release-package smoke suite. The
tests prove that origin-form and legacy `/api` settings both produce the same `/api` requests, while HTTP, credentialed,
query-bearing, and arbitrary-path URLs fail closed. This is source/build evidence only; v0.13.6 remains the latest
candidate exercised through an installed Dynatrace tenant Workflow.
