# v0.13.6

## Operator-visible diagnostic evidence

- Displays the declared Forward access profile, check time, and correlation ID after **Test connection** succeeds.
- Keeps the response bounded and redacted: credentials, Credential Vault IDs, Forward network and snapshot IDs, request
  endpoints, and raw response bodies are not rendered.
- Preserves the v0.13.5 read-only diagnostic behavior and its GET-only Forward API boundary.
- Adds a recorded development-tenant positive control for a bounded, allowlisted Forward Library NQE through the
  installed on-demand Workflow action.

## Upgrade note

Deploy v0.13.6 as a new immutable app version. Dynatrace correctly rejects replacing an installed version with different
content under the same version number.

The positive control does not close application-flow acceptance: a tenant must still supply current distributed-trace
or OneAgent network-flow rows and complete an `operation: plan` Workflow against those observed dependencies.

## Internal test verification

The final v0.13.6 candidate was verified twice through the installed on-demand Workflow action in the internal
Dynatrace test tenant. The final run completed successfully in five seconds under Read Only, executed the allowlisted
Forward-owned Library query with a one-row maximum, and returned only bounded aggregate evidence and column names.
This verification did not use a customer Dynatrace environment and does not claim observed application-flow
acceptance.
