# Forward for Dynatrace v0.13.0

This enterprise preview hardens the direct Forward API boundary, makes approval and reconciliation behavior explicit,
and moves arbitrary NQE execution to Forward's asynchronous execution contract. It remains intended for controlled
evaluation and non-production design-partner use. The immutable GitHub release record supplies the publication time
and exact tag commit.

## Highlights

- Prevents retry of mutating Forward requests, rejects redirects, caps streamed responses, applies an invocation-wide
  deadline, bounds retry delays, and refreshes CSRF state at most once.
- Requires successful modeled-path evidence before Network Admin apply and re-reads Forward state immediately before
  the first mutation.
- Validates dependency rows at the action boundary and binds approval to the network, snapshot, mutation budget,
  complete planned state, and existing managed-check fingerprints.
- Enforces the full managed-check ownership tuple and fails closed on duplicate keys, foreign ownership, unexpected
  inventory response shapes, drift, and partial failure.
- Adds strict TypeScript coverage for the credential-handling and mutation core with shared runtime contracts.
- Moves every Forward username and password into an APP_ENGINE-scoped Dynatrace Credential Vault entry; app settings
  retain only the `CREDENTIALS_VAULT-*` entity reference.
- Adds explicit distributed-trace and OneAgent network-flow discovery profiles so instrumented and non-instrumented
  application dependencies can use separate reviewed tenant queries.
- Uses Forward's asynchronous NQE execution API, supports safe resume by execution key, and separates submit from
  idempotent status and result polling.
- Adds optional engine approval, approval nonce and expiry, exact partition selection, and a 500-update invocation
  ceiling while preserving Read Only and Network Operator plan-only behavior.
- Refreshes the sync, NQE, and evidence UI to expose approval, collision, stale-plan, mutation, and verification state
  without returning credentials, raw queries, rows, or detailed path topology.
- Removes the unused client-side router from the single-page app and pins the Dynatrace archive tool to a patched ZIP
  dependency; the production dependency audit is clean at release-candidate validation time.

## Security, RBAC, And Data Boundary

- Read Only can execute only configured Forward Library NQEs by ID and cannot write checks.
- Network Operator can execute separately approved arbitrary NQEs and remains unable to write checks.
- Network Admin can create or update only the exact approved managed checks; deletion is not implemented.
- Credentials remain in Dynatrace Credential Vault and are resolved only by app functions. Browser, app settings, and
  Workflow results remain sanitized and bounded.
- The unused unbounded Forward status proxy and its environment-entity read scope were removed.

## Breaking Changes

- The Forward API connection settings schema is `3.0.0`. Raw username/password settings are removed; every connection
  must reference an APP_ENGINE-scoped username/password entry in Dynatrace Credential Vault.
- The dependency discovery profile schema is `2.0.0` and requires an explicit `distributed-traces` or `network-flows`
  source type. Existing discovery profiles must be recreated or updated before execution.
- Network Operator and Network Admin arbitrary NQE requests now require `approvedQueryDigest`, and the connection must
  allow that digest through `approvedQueryDigests`. Library NQE execution by approved query ID is unchanged.
- Callers that use arbitrary NQE must update their request and connection settings before upgrading. The release fails
  closed instead of silently accepting the older request shape.

These contract changes require a minor release under the preview compatibility policy; this release supersedes the
unpublished `0.12.2` development candidate.

## Validation

- Complete Node.js 24 CI and release gates, including strict type checking, lint, build, schema, security, release,
  checksum, signature, SBOM, and immutable-ref tests.
- A 1,000-relationship scale cycle and 100-cycle deterministic reconciliation soak.
- Live non-production Read Only planning over 1,000 current dependencies and modeled paths with zero reconciliation
  drift or ownership collision.
- Live non-production negative mutation tests plus bounded create/update readback and restoration.

Live validation does not prove production-scale mutation, multi-tenant concurrency, failure injection against a live
Forward service, independent audit retention, or signed production distribution.

## Upgrade And Rollback

1. Export the current Dynatrace app settings through the tenant's approved backup process.
2. Create a dedicated Forward service identity in Dynatrace Credential Vault and update every Forward connection with
   its Vault entity ID. Populate `approvedQueryDigests` before invoking arbitrary NQE.
3. Install only the verified `v0.13.0` archive and begin with Read Only planning.
4. Re-plan after upgrade; do not reuse an approval digest, nonce, or execution key from an earlier version.

Application rollback does not reverse Forward intent-check changes. To roll back the app, stop write-enabled Workflows,
retain the Forward audit record, remove the preview app through the approved tenant process, reinstall a verified prior
archive, and restore only settings compatible with that version.

## Known Limits

- Sequential check updates are limited to 500 per invocation because Forward has no supported bulk PATCH contract.
- Concurrent apply is detected through state and digest revalidation but is not prevented by a durable distributed lock.
- Engine approval proves that the automation engine approved the request; it does not supply a typed human identity.
- Stale checks remain report-only, and duplicate or foreign managed identities require operator resolution.
- Signed `com.forward.dynatrace` distribution and independent security/privacy review remain external promotion gates.

## Installable

`forward-dynatrace-app-v0.13.0.zip` is the only installable artifact. The CycloneDX SBOM, `SHA256SUMS`, optional detached
signature, and GitHub attestations are verification evidence. Forward requires no software from this project.

Download every asset from the same release, run `sha256sum -c SHA256SUMS`, and verify the app and SBOM attestations
against `forwardnetworks/forward-dynatrace` before installation.
