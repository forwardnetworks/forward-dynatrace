# Forward for Dynatrace v0.13.2

This patch restores installation on current Dynatrace tenants while preserving the Credential Vault security
boundary introduced in v0.13.0.

## Settings Schema Compatibility

- Advances `forward-api-connection` to schema version `3.0.1` because Dynatrace settings schema versions are
  immutable after registration.
- Removes obsolete `forceSecretResubmission` metadata from the Vault-reference-only schema. The schema stores a
  `CREDENTIALS_VAULT-*` entity ID, not an inline username, password, or secret.
- Adds a repository regression gate that rejects raw credential properties, inline secret types, secret-resubmission
  metadata, and `SECRET_RESUBMISSION` constraints in the Vault-backed connection contract.

## Installation Diagnostics

- Reports bounded AppEngine subresource failure details when an installation ends in `ERROR`, so schema deployment
  failures identify the affected resource without exposing the bearer token.

All Forward API behavior, least-privilege access profiles, dual-source dependency discovery, mutation controls, and
release provenance requirements remain unchanged from v0.13.1.

## Installable

`forward-dynatrace-app-v0.13.2.zip` is the only installable artifact. Download all assets from this release, verify
`SHA256SUMS`, validate the optional detached signature when present, and verify the app and SBOM attestations against
`forwardnetworks/forward-dynatrace` before installation.
