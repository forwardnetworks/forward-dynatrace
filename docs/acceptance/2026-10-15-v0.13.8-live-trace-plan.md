Date: 2026-10-15

This record covers an unsigned trial-tenant deployment against a lab network. It is a product positive control
for the application-flow path that the v0.13.6 record left open. It is not customer-sandbox or production acceptance.

Execution identifiers, snapshot IDs, hostnames, and addresses are retained in ignored local evidence, not in this record.

## Findings

- A DQL long reaches a Workflow task as a string. The sync action rejects a string `confidence`, so the Workflow query
  casts it with `toDouble(...)`. The action should arguably accept a numeric string.
- The plan output is aggregate counts only. Per-flow detail comes from Forward's path search.
- The `consistent-with-network-policy-block` assessment label was returned for a missing route. The label is coarse.
- The plan digest binds the snapshot, so the same network state in a new snapshot produces a new digest.
- The repository CI did not catch the schema defect. The v0.13.8 change adds a validator rule for greedy quantifiers
  inside regex groups.
- Full `npm run ci` currently fails at `security:audit` on transitive dependency advisories. The identical advisories
  are present in the committed v0.13.7 lockfile, so they predate this change. All other CI steps pass.

## Still open

- The Connection Diagnostic button in the installed app was not exercised. The diagnostic function was called from
  outside the app, where it correctly reports `credential-vault-invalid` because there is no app context.
- Network Admin apply was not run against v0.13.8.
- The lab's firewall tier did not boot, so these flows are branch-to-branch only.
- This is a lab network, not customer application-flow acceptance.
